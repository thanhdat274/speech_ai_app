# SparkSkill - Claude Code Configuration

SparkSkill: Structure + Automation + Quality = Developer Happiness

## SparkSkills (Improved Workflow)

### Creation Phase
- `/spark.init <name>` - Initialize new project
- `/spark.brainstorm` - Refine ideas through questioning
- `/spark.constitution` - Create project principles
- `/spark.specify` - Describe WHAT to build
- `/spark.plan` - Technical implementation plan

### Implementation Phase
- `/spark.tasks` - Break into bite-sized tasks
- `/spark.implement` - Execute with TDD (RED-GREEN-REFACTOR)
- `/spark.review` - Two-stage code review
- `/spark.debug` - Systematic root cause analysis

### Workflow
- `/spark.worktree` - Git worktree management

## Legacy OpenSpec Commands

Continue to work for backwards compatibility:
- `/opsx:new <name>` - Start new change
- `/opsx:propose <name>` - Create with all artifacts
- `/opsx:apply <name>` - Implement tasks
- `/opsx:verify <name>` - Verify implementation
- `/opsx:archive <name>` - Archive completed change
- `/opsx:explore` - Explore requirements
- `/opsx:ff <name>` - Fast-forward creation
- `/opsx:onboard` - Guided onboarding

## Recommended Workflow

**New projects**: Use SparkSkill for better structure
**Existing projects**: Continue with OpenSpec or migrate to SparkSkill
